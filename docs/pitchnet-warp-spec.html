1概覽

PitchNet 是開源的人聲修音軟體：偵測音高、切成音符，修過的音符用神經聲碼器重新合成。這個 fork 起初只想解決一件事——原版的音符「拉不長」——後來一路擴大到聲音處理、編輯行為、專案檔，以及讓 AI agent 修音。

這一頁照事情發生的順序排：先是決定方向的試聽研究（第 2 節），再是各部分的設計（第 3～9 節，每節依「問題 → 決定 → 原因」排列），最後是還沒決定的事和實作紀錄（第 10～12 節）。第一次看建議照順序讀；找特定決定可以用左邊目錄裡的 Q 編號。

聲碼器為什麼會壞

聲碼器不是直接處理錄音，而是拿兩樣東西重新「畫」出聲音：從原始錄音算出的頻譜（mel），和一條音高曲線。音高曲線是哪一種、素材是哪一種，決定了結果。

那為什麼 PitchNet 修起來很自然

因為 PitchNet 只重新合成你改過的那幾個音符，句子其他部分都是原始錄音。這次的測試則是把整段（包含底噪、空隙）都送進聲碼器，在品質差的素材上等於把麻感放大到整個檔案。

問題與根因

另外兩個已確認的問題

  • 多選邊界一起拖，只會整組平移，不能按比例縮放整句。
  • 多選拖曳的範圍，是所有選到的邊界各自限制的交集。只要其中 1 條碰到硬塊，整組都會被卡住；交集不存在時，範圍直接變成 0，而且畫面上沒有任何提示。

架構

時間資料
只存在伸縮層：一串 warp 錨點，每個錨點記錄「原始錄音的時間 → 伸縮後的時間」。PitchNet 現在有 3 套各自運作的時間規則：音符伸縮、音符之間空隙被覆蓋、區段前導和尾巴只能平移。這 3 套合併成整條音軌共用的一張時間對應表；合成、畫面、音高曲線、呼吸音符、undo、存檔全部改讀這張表。
音符位置
存在原始錄音的時間上，伸縮層一動，音符和音高曲線自動跟著走。跟 Cubase 的做法相同。
音符層的職責
只管音高。拖音符邊界只是介面上的捷徑，結果寫進伸縮層。
圖層順序
伸縮層在上，音符層在下。
錨點之間的伸縮
等比例：子音、母音、空隙一起伸縮。要保住子音，由使用者自己在子音前後放錨點。整句伸縮時，每個子音分到的變化量很小，只有拉很長或縮很短時才會聽出來。
移除的舊邏輯
PitchNet 原本「保住子音、只拉母音」的音符計時（NoteTimeMap），以及區段前導和尾巴的硬塊。
GAME 區段
只留給模型推論用，不再影響編輯。分析時還是要切：PitchNet 一次最多送 5000 幀（約 50 秒）給 GAME，GAME 官方的推論程式也一樣先切再送，門檻設定（-40 dB、1000 ms、200 ms、100 ms）完全相同。GAME 訓練時加過噪音和殘響的資料擴增，切出來的片段帶有底噪不是問題。
舊存檔（Q3 定案）
不支援。讀到舊格式的 .pitchnet 檔或外掛狀態時，顯示「此檔案來自舊版 PitchNet，無法開啟」之類的提示，不嘗試轉換。目前沒有任何正式專案用到 PitchNet，本機也找不到 .pitchnet 檔。舊存檔的時間資料只有每個音符的原始位置和目前位置：音符內部的伸縮可以換算，但舊版在空出的位置填靜音、前導和尾巴整塊平移，新的連續時間對應表無法重現，換算後聲音會不同。fork 可以用建置選項 PITCHNET_DEV_BUILD 建成「PitchNet Dev」（外掛代碼 PTD1，官方是 PTE1），跟官方版同時安裝、互不讀取對方的狀態。
暫不採用
保留現有架構，只把區段的前導和尾巴改成可以伸縮。改動較小，能解決被擋住的問題，但 3 套時間規則還是各自運作，撐不起獨立的伸縮層。改用統一的時間對應表之後，硬塊會自然消失。

長度與比例限制（Q2 定案）
每段至少 1 格、比例 12.5%～800%；超出 0.5～2 倍只提示、不阻擋。操作方式見本節「操作」。1 格（11.6 ms）是聲碼器的最小時間單位，也是 PitchNet 現在每個音符的下限（TimingHandler.cpp 的 + 1.0f）。長度 0 等於刪除那段原始錄音，時間對應表會無法反推。12.5%～800% 跟 iZotope RX 的 Time & Pitch 相同。signalsmith 在 0.5～2 倍之外品質沒有保證：壓縮超過 2 倍時相位只算到 2 倍（timeFactor 下限 0.5），拉長超過 2 倍時開始隨機化相位；這點是從程式碼推論的，沒有試聽過。跑拍修正小於 1/8 拍時碰不到這些限制。

第 4 節決定「改了音高的音符用聲碼器」。實際修一整首歌之後發現，聲碼器會讓某些音的質感變掉。這一節記錄成因、量測、已經做的補救，以及下一步的架構。實作細節與驗證數字在第 11 節的 Q12 各列。

起因
使用者回報煙幕 02:48.124「天地的地」（E5，約 670 Hz）只修 -0.29 半音卻聽得出瑕疵：原聲有一種「麻感」，聲碼器重新合成後變成「電感、鬆散抖抖」。只重新合成、不移調也一樣變質，所以跟修正量無關。使用者說明麻感在 10 kHz 以上。
量到的成因
聲碼器把高頻裡「跟聲門週期同步的諧波」換成了雜訊。「地」在 10.5～15 kHz 的同調成分少 10.2 dB，包絡週期性從 0.53 掉到 0.07；雜訊成分不變，所以整個高頻帶少 3.4～4.4 dB。量法：把訊號依基頻相位重新取樣，每個諧波拆成跨週期穩定的同調成分與逐週期起伏的雜訊成分（試聽工具/harmonic_coherence.py、coh_check.py）。先前量過的高頻能量、空氣聲、HNR、次諧波、振幅與音高的快速起伏、頻譜形狀都抓不到。Core ML 與 ONNX CPU Float32 結果相同，跟推論精度無關。03:01.789 的 E5 原聲在這個頻帶的同調成分本來就低 7 dB，損失小，跟使用者只聽出「地」一致。只有 2 顆音的資料，自動判斷的門檻還定不出來。
驗證：分頻混合
在 5.03 kHz（第 7、8 諧波之間）分頻：聲碼器低頻＋原聲高頻有麻感；原聲低頻＋聲碼器高頻沒有。聲碼器的 5 kHz 以下不會破壞麻感，問題只在高頻（高音試聽/13）。

修過的音伸縮後，曲線重新貼合錄音

6音符與音高曲線

相鄰音符的判斷
合併音符、剪刀工具的合併線、音高曲線相連，這 3 個功能拿掉「同一個區段」的條件，只看兩個音符是否緊貼。區段由音量門檻決定，跟畫面上的音符排列無關。例如把第一句尾音拉到貼上第二句的短音，兩個音符在畫面上緊貼，卻分屬不同區段，音高曲線會斷開、也不能合併。
切分、黏合、刪除、拉伸後的音高
比照 VariAudio：先把所有音符暫時切回未編輯狀態，在未編輯的音高上計算音符的分析中心（originalMidiNote）、分析曲線（originalDeltaPitch）和邊界補償，再把各音符的移調和音高工具放回去。黏合後的音符回到分析音高；被切開的音符兩半保留原本的移調。原本直接在含移調的音高上計算，已移調片段或鄰居的移調會被寫進分析曲線，黏合或刪除後白線出現多個半音的斷層（測試素材女友感台本第二版，Note 98–100）。只帶已烘焙曲線的鄰居，回到編輯狀態後再補償一次，維持原本唱的音高；只移調的鄰居，邊界附近跟著新的基準音高平滑過渡。實作在 NoteSplitter.cpp 的 UneditedSpace。
未編輯音符的音高
依「所有音符都未編輯」時的基準音高貼回錄音：鄰居沒移調時完全等於錄音；鄰居移調時，邊界隨基準音高平滑過渡到鄰居。拖音高、Reset、拉邊界、切分、黏合、刪除、伸縮後都照這個標準。使用者選擇平滑過渡（2026-11-16）。原本貼回時用含鄰居移調的基準，貼回結果會隨當下鄰居狀態改變：同一顆音符拖音高時平滑、Reset 後卻直接跳過去，而且拖音高再 Reset 鄰居、一路 undo 後留下尖角（測試 0.78 半音）。改成未編輯基準後，未編輯音符的曲線只跟錄音有關。實作在 PitchCurveProcessor::refitUntouchedCurves。
還原選單不含時間
音符的還原選單只有「音高」「共振峰」「振幅」「音符切點」與「全部編輯」（Restore All Edits）；時間（warp 錨點）只在伸縮工具裡操作，用 Alt＋左鍵刪除錨點還原。Restore All Edits 也不動時間。使用者決定（2026-11-21）：把時間跟音高、切分合併等操作分開，時間專心交給垂直線與紅藍區域。原本的「時值」項目與 Restore All Edits 只移除落在選取音符原始範圍內的錨點，範圍外拖過的錨點留著，使用者實測時看起來像沒還原（01:54，錨點在原錄音第 9894 格，不在選取的音符內）。
Restore All Edits 的順序
先還原音符切法，再把未編輯的音符貼回錄音音高。重切音符時對鄰居曲線做的補償也記錄進 undo。

7試聽

點音符試聽
比照 Cubase：只播被點的那一個音符，從頭播到尾，播的是編輯後的實際結果。取代原本「從前一個音符播到後一個音符」（原本的範圍是同一個區段內的前後音符）。不採用 Melodyne 那種按住時循環播放一小段的方式。
試聽的觸發
在音符上按下滑鼠就播放，取代原本要先等試聽按鈕出現再點的方式。播放會一路播到音符結尾，跟滑鼠何時放開無關。PitchNet 在選取模式下，按住音符本來就會開始改音高；按下後如果拖曳，就變成改音高，試聽方式見下一項。
拖音高時的試聽
播放聲碼器合成的實際結果：整顆音符循環播放，每輪之間停 0.5 秒；拖到新音高時重算這顆音符，從原播放位置接著播並交叉淡化。獨立版與外掛（ARA）行為相同。取代原本把原始錄音變速移調、循環播放的近似效果。循環播放由使用者確認（2026-11-16），原本這裡寫「只播一次」。實作前的調查：原本 PitchNet 只在放開滑鼠時才重新合成（onPitchEditFinished），拖曳中聽到的都是近似效果。它的合成本來就是在背景執行：新的請求會中斷還沒算完的那一次，改算最新的音高（EditorController 的 pendingRerun）。所以拖曳中可以一再送出合成請求，只會算到最新的音高；畫音高曲線的工具已經是這樣邊畫邊合成。合成需要時間，音高改變後要等合成完成才會聽到新版本；這段延遲有多長，文件沒有寫，要建置後實測。

9AI agent 修音（Q9 定案）

AI agent 修音：agent 直接改 .pitchnet 的音符，改完執行 WarpRender 新檔 輸出 --apply --before 原檔 重新合成。

起點：SLEEP FREAKS 2026-11-12 的短片（x.com/SLEEPFREAKS_DTM/status/2120817056505544837）：把未編輯的 .pitchnet 和導引旋律 MIDI 交給 Codex，依約 12 行規則修音，再在 Cubase 用 Insert 掛 PitchNet 打開新檔比較。影片沒有交代 agent 怎麼把修改合成成聲音。
根因（圖解 1）：.pitchnet 存了整首播放用的聲音（waveform），打開檔案時直接播放，不會照音符重新合成；開檔時也沿用檔案裡存的音高曲線。只改音符數字，獨立版、Insert、ARA 都聽不到。
解法（圖解 2、3，使用者決定）：agent 呼叫 PitchNet 本體合成。--apply 先照音符重建音高曲線，跟原檔逐格比對，只重算有差異的音符，寫回 waveform 後存檔。
不採用：刪掉 waveform 改走重新合成的開檔路徑（整首變成聲碼器聲音，跟原錄音相比訊噪比 -2.8 dB）；agent 自己寫腳本跑聲碼器（混合遮罩、接縫相位對齊、伸縮對應都要另外重寫，難以跟 PitchNet 一致）；開檔時補算；agent 手動拿掉 renderedEdit；改存檔格式記錄合成參數。
進度：已完成 --apply（e1dcba1）、給 agent 的規則（f2e3aa9，見本節「給 agent 的規則」）、獨立版 App 與 Cubase 14（Insert、ARA）實機驗證；實驗紀錄見本節最後。待測（音量與共振峰、切音符等）集中在本節「待測」。

給 agent 的規則

這份規則給直接修改 .pitchnet 音符數字的 AI agent 使用。目前只涵蓋「改音符音高」；其他修改都在「待測」，驗證前不要做。「規則 1～5」每一條都有實測根據，根據寫在「驗證紀錄」。

規則 1：為什麼一定要執行 --apply

  1. .pitchnet 裡存了整首播放用的聲音（waveform）。
    打開檔案時直接播放它，不會依照音符重新合成。
  2. 只改音符數字，播放的聲音不會變。
  3. WarpRender --apply 會重新合成有改到的音符，寫回 waveform 後存檔。

規則 2：工作流程

  1. 開始修改前，先把要改的檔案複製一份，當作這一輪的「原檔」。
    例：cp song.pitchnet song.before.pitchnet
  2. 修改另一份（「新檔」）的音符，依照規則 3。原檔不要動。
  3. 執行：
    WarpRender 新檔.pitchnet 輸出.pitchnet --apply --before 原檔.pitchnet
    1. WarpRender 位置：PitchNet/out/dev/tests/WarpRender
    2. 沒給 --before 時：印出用法、結束碼 2、不產生輸出檔。
    3. 成功時：結束碼 0，最後一行是「synthesized N notes, wrote 輸出檔路徑」。
  4. 依照規則 4 檢查結果。
  5. 把「輸出.pitchnet」交給使用者。
  6. 連續修改多輪時，每一輪的原檔是上一輪的輸出檔。
    不要拿最初的檔案當原檔，否則前幾輪的音符會再合成一次，聲音會有細微差異。

規則 3：怎麼改音高

  1. 只改 rest 為 false 的音符。
  2. 改 midiNote，並把 lastNonMacroMidiNote 設成相同的值。
  3. pitchOffset 保持 0。最終音高 = midiNote + pitchOffset，
    兩個欄位都加 3 會變成移 6 個半音。
  4. 單位是半音（MIDI 音高，60 = C4，可以有小數）。
    移調 n 個半音：midiNote = 目前的 midiNote + n。
  5. 改回原音高：midiNote 設成 originalMidiNote。
  6. 除了 midiNote 和 lastNonMacroMidiNote，其他欄位都不要改。
    不要自己改 JSON 來切開、合併、刪除音符，也不要改 startFrame、endFrame、rest：
    這些修改 --apply 不會合成，或結果跟 App 不同（見「四項驗證結果」）。
    切開、合併、刪除之後會改由 App 的程式執行，正式指令完成前先不做。
    要取消某個音符的修改，把 midiNote 設回 originalMidiNote，不要刪掉音符。
  7. 用 JSON 函式庫讀進整份檔案，改完整份寫回。

規則 4：找音符與檢查結果

  1. 時間換算：音符的 startFrame／endFrame 單位是格，1 格 = 512 個取樣，取樣率 44100 Hz。
    秒數 = 格數 × 512 ÷ 44100。
  2. --apply 的輸出應該符合：
    1. 「changed frames [起,迄)」落在改過的音符範圍，前後各多幾格是音高曲線的過渡。
    2. 「note @起始格」列出的就是改過的音符。
    3. 「synthesized N notes」的 N 等於改過的音符數。
    4. 最後一個音符之後的空白格子也可能被列為不同，不影響結果。
  3. 再用比對指令確認：
    WarpRender 原檔.pitchnet 輸出.pitchnet --diff
    每個改過的音符列一行，移 n 個半音的音符，最大差距約 n × 100 cents。
  4. 結果不符合時，不要交出輸出檔；回報指令、完整輸出和改過的音符。
